## FINDINGS
(#: file — quoted line/sentence — what could go wrong when implemented)

1. `docs/03-board-generation.md`, line 86: "Budget: ≤ 3 materializations per brief, ≤ 3 briefs total (≤ 9 attempts per POST /api/games)." — This board-generation retry budget is a tunable number hardcoded outside `config.json`, but `docs/00-project-overview.md` line 46 places "the AI-retry knobs" in the config and `docs/08-agent-rules.md` rule 13 says "The config is the ONLY place" for such numbers. What could go wrong: one agent hardcodes 3/3/9 (violating rule 13), another invents a config key not specified in `03` (deviating from the fixed budget), producing inconsistent retry behavior and failing the spec's "single source of truth" rule.

2. `docs/06-api-contract.md`, line 124: `"winRate": 0.583,` — `winRate` is defined only by example; the doc never states what it equals when `gamesPlayed` is 0. What could go wrong: division by zero yields `NaN`/`Infinity`, the server omits the field, or the client renders "NaN" — agents invent different behavior with no spec to arbitrate.

3. `docs/06-api-contract.md`, lines 159-163 and 169 (`POST /moves` — "Exactly ONE successful POST /moves per round"), together with `docs/05-frontend.md` line 93 ("End turn still works" with "staged ≤ 0 moves") — whether an empty `moves` array is a valid submission (consuming the one-success budget) or a 400 is unspecified. What could go wrong: one agent forces the player to submit a dummy `wait`, another accepts an empty bundle and locks the round, changing turn-flow behavior.

## AMBIGUITIES

Interpretation A: `byDifficulty` always returns all three personalities (including zero-played ones). Interpretation B: it returns only difficulties with ≥ 1 played game. The doc never says.

2. `docs/06-api-contract.md`, line 124: `"winRate": 0.583,` — Interpretation A: `winRate` = 0 when `gamesPlayed` = 0. Interpretation B: `winRate` = `NaN`/`null`/omitted when `gamesPlayed` = 0. No rule is given.

3. `docs/06-api-contract.md` lines 159-163/169 plus `docs/05-frontend.md` line 93 — Interpretation A: an empty `moves` array is a valid `/moves` submission that locks the round (one-success budget consumed). Interpretation B: an empty bundle is invalid (400); the player skips `/moves` and goes straight to `/end-turn`.

## CONTRADICTIONS
(#: file A quote vs file B quote)

1. `docs/02-game-rules.md`, line 87: "the FINAL tiles of the bundle must be distinct and empty in the pre-move state"; line 44: "a unit can never end movement on an occupied tile"; line 86: "isPathLegal passes for every move" — vs `docs/02-game-rules.md` line 92: "Wait: legal anywhere."; `docs/05-frontend.md` line 81: "click [Wait in place] → stage wait for same tile"; `docs/06-api-contract.md` lines 160-162 (`{ "unitId": "P-archer-1", "path": [[9,9]], "action": { "type": "wait" } }`) and line 165: "the final tile must be empty." A `wait` move's path is a single entry at the unit's own current tile, which is occupied — so the landing-tile/path-legality rules literally reject `wait`, while three other passages explicitly permit it. An implementer following the literal rule breaks turns; exempting `wait` is never specified.

2. `docs/01-architecture.md`, line 137: the AI job updates the row to "(player_turn | won | lost, clears ai_last_error)" — implying `won` is an AI-job outcome — vs `docs/06-api-contract.md`, line 189: "ai_turn → won does NOT exist — the AI can never destroy its own army, so a player victory is only ever produced by endpoint 13." Since the AI cannot wipe its own army, `won` never results from the AI job, contradicting `01`'s inclusion of `won` in that update path.

## VERDICT
Top 3 findings, ranked, one sentence each.

1. The wait-action versus landing-tile contradiction (`docs/02` vs `docs/02`/`05`/`06`) is the most dangerous because it makes a documented legal move either unimplementable or silently rejected, breaking turn execution entirely.
2. The board-generation retry budget living outside the config file (`docs/03` vs `docs/00`/`08`) forces agents to choose between hardcoding a tunable (breaking rule 13) or inventing unspecified config keys, destroying the single-source-of-trust guarantee.
3. The `winRate`, `byDifficulty`, and empty-`moves` silences in `docs/06` let independent agents ship statistically and behaviorally incompatible APIs with no spec to arbitrate between them.
