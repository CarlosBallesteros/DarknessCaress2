## FINDINGS

1. **docs/02-game-rules.md (lines 34–38, 97) vs docs/00-project-overview.md (line 46) / docs/01-architecture.md (config shape) — the engine's config projection cannot express the fixed army.**
   - Quote (02): `export interface GameEngineConfig { // projected from server/config.json — the engine never reads the file
     classes: Record<ClassKey, { hp: number; atk: number; def: number; mov: number; range: number[]; healAmount?: number; role?: ... }>; }` — the per-class `count` is absent from the type.
   - Quote (02, line 97): "…the sum of `config.classes[*].count`: 2+2+2+2+1+1".
   - Quote (00, line 46): "Game logic must read values from this file — stats are never hardcoded, inlined, or duplicated."
   - What could go wrong when implemented: an agent cannot build the 10-unit army from the projected `GameEngineConfig` as specced; the constitution and the turn semantics both assume `count` exists somewhere it isn't declared. Two agents could resolve this by hardcoding the army, adding `count` to the projection, or having the engine read the file — a direct violation of the single-source-of-truth rule either way.

2. **docs/05-frontend.md (line 84) vs docs/06-api-contract.md (line 171) — end-turn choreography is internally inconsistent/underspecified.**
   - Quote (05): "staged → playerTurnSubmitted   ([End turn] → POST /moves (staged list) → POST /end-turn → status ai_turn)".
   - Quote (06, line 171): "No concept of 'partly acted units' — moves were already applied atomically by endpoint 13, so ending the turn is pure state transition (any un-acted units simply do nothing this turn)."
   - Quote (05, line 93): "if staged ≤ 0 moves but some unit(s) have `acted=false`, End turn still works (they do nothing) — button always enabled, confirm dialog only when un-acted units remain."
   - What could go wrong when implemented: when the staged list is empty, the docs never say whether the client sends `POST /moves` with an empty bundle or skips straight to end-turn — and the contract for empty bundles is never addressed.
