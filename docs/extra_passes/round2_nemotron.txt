## FINDINGS

1. **docs/01-architecture.md line 137** — stale recovery re-triggers AI jobs where `status = 'ai_turn' AND now() - updated_at > config.ai.staleAfterSeconds`; **docs/04-ai-integration.md line 154** — after 3 failed AI attempts the job writes `ai_last_error`, leaves `status = ai_turn`, `turn_number` unchanged, but never says whether `updated_at` is bumped. What could go wrong: an agent cannot determine whether a stalled/failed AI turn is re-triggered 60 s after `end-turn` or 60 s after the failure; recovery timing is invented per agent.

2. **docs/06-api-contract.md line 176** — `POST /api/games/:id/forfeit` — from `player_turn` or `ai_turn` → `status = "lost"`; **docs/01-architecture.md line 137** — the AI turn is a fire-and-forget background job that writes game state on completion. What could go wrong: if a player forfeits while an AI job is still running, the job may complete afterward and overwrite `status = "lost"`; no arbitration is specified, so a forfeit can be silently undone.

3. **docs/06-api-contract.md lines 106-131** — `GET /api/stats` example shows `byDifficulty` with all three personas at `played > 0`; **docs/00-project-overview.md line 33** — Statistics shows "wins/losses per AI difficulty — computed from finished game rows." What could go wrong: it is unspecified whether a difficulty with zero finished games appears as a zero row or is omitted entirely; two agents will emit different stats shapes.

## AMBIGUITIES

1. **docs/07-assets.md line 25** — `assetPath(themeId, kind, variant)` returns `/assets/{themeId}/{…}` with only theme/kind/variant; **docs/05-frontend.md line 89** — sprite path is `/assets/${theme}/${class}/sprite-${side}.png`, which needs both `class` and `side`. Interpretation A: pack class+side into `variant`; Interpretation B: the helper needs an additional `class` argument not in the spec. The agent must invent the encoding.

2. **docs/04-ai-integration.md line 165** — hygiene rule: grid references ("15x15") are rendered from `config.boardSize`; **docs/04-ai-integration.md lines 39-41** — the turn system prompt hardcodes "on a 15x15 grid", "x columns 0-14", "y rows 0-14" with no placeholder. Same split in **docs/03-board-generation.md line 10** (grid size "comes from config.boardSize") vs **line 13** (literal "15x15 grid", no `« »` swap). Interpretation A: templates hardcode 15×15; Interpretation B: templates render `config.boardSize` via a placeholder not shown.

3. **docs/00-project-overview.md line 33** — stats include "wins/losses per AI difficulty"; **docs/06-api-contract.md lines 106-131** — `byDifficulty` example shows all three personas with `played > 0`. Interpretation A: always list all three personalities (zero rows included); Interpretation B: list only difficulties with at least one finished game.

4. **docs/05-frontend.md line 9** — `DEFAULT_THEME constant = config.themes[0]`; **docs/01-architecture.md line 131** — "the frontend never reads the file directly." Interpretation A: `DEFAULT_THEME` comes from `GET /api/meta` (`themes[0].id`); Interpretation B: the frontend reads `config.json` directly, violating the stated rule.

## CONTRADICTIONS

1. **docs/03-board-generation.md line 88** — "Record in the game row that the fallback fired (for stats/debug)." vs **docs/01-architecture.md lines 86-98** — the `games` table columns are `id, user_id, difficulty, status, board, units, turn_number, ai_last_error, created_at, updated_at`; there is no column to record a fallback firing. Required data has no storage.

2. **docs/04-ai-integration.md lines 39-41** — the turn prompt hardcodes "on a 15x15 grid", "x columns 0-14", "y rows 0-14" vs **docs/04-ai-integration.md line 165** — grid references are rendered from `config.boardSize`; also **docs/03-board-generation.md line 10** (grid size from `config.boardSize`) vs **line 13** (literal "15x15 grid", no placeholder). The same spec contradicts itself on whether board size is templated or hardcoded.

3. **docs/07-assets.md line 25** — `assetPath(themeId, kind, variant)` vs **docs/05-frontend.md line 89** — the required sprite path embeds both `class` and `side`. The specified helper signature cannot produce the specified path format.

## VERDICT

1. The fallback-fired requirement (docs/03 line 88) cannot be implemented as written because the `games` schema (docs/01 lines 86-98) has no column to store it — the clearest spec breach.
2. The `assetPath` helper (docs/07 line 25) is underspecified against the sprite/portrait path format (docs/05 line 89), so two agents will build incompatible asset loaders.
3. The board-size references in the LLM prompts are simultaneously claimed config-driven and hardcoded 15×15 (docs/04 lines 39-41 vs line 165; docs/03 line 10 vs line 13), forcing every agent to guess the templating mechanism.
