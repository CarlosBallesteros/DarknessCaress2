# Spec Audit — Darkness Caress II

Reading only the named docs (README, 00–10). No files touched, no commands run.

## FINDINGS

1. **docs/01-architecture.md (DB schema) vs docs/06-api-contract.md (DTO) — the AI-actions field has no database home.**
   - `01` (lines 86–99): the `games` table columns are `id, user_id, difficulty, status, board, units, turn_number, ai_last_error, used_fallback, created_at, updated_at` — there is no column for AI actions; the doc calls the schema "exact" (line 72).
   - `06` (lines 52–59, 138): `GameState.lastAiActions` is mandatory ("set after an AI turn applies; REPLACED by the next AI turn, null at creation…") and the AI job persists "lastAiActions = the events list mapped to the AiAction DTO in 06".
   - What could go wrong when implemented: an agent must invent persistence/mapping despite the no-invention fence (`08`, rule 7) and the "exact" schema claim — either silently deviating or escalating mid-phase.

2. **docs/02-game-rules.md — internal contradiction on the landing-tile rule.**
   - Line 89: "…a unit may NOT end on a tile that only becomes free because an **earlier** bundle entry vacates it (no chain-following…)".
   - Line 137: catalogue offers "`tile (x,y) frees later in this bundle and cannot be landed on`".
   - What could go wrong: the conflicting phrasing ("earlier" vs "later") lets two agents write different validators.

3. **docs/06-api-contract.md — internal contradiction in `PATCH /api/me`.**
   - Line 98: "…send ANY ZERO OR MORE of `username`/`theme`; **at least one key must be present**."
   - What could go wrong: the partial-update zod schema is self-contradictory; agents must resolve it before implementing.

4. **docs/04-ai-integration.md — mock-LLM fixture content unspecified.**
   - Line 25: the mock "returns recorded/fixture JSON responses" — no fixtures enumerated.
   - What could go wrong: retry-loop and E2E behavior depends on fixture content no doc pins; agents invent it, then bless invented behavior via tests.

## AMBIGUITIES

1. **docs/04 (lines 82–86) — STATS line format.** "`Format, exactly: <class>=hp<hp>/atk<atk>/def<def>/mov<mov>/rng<range>/role<role>`" and "`/heal<n>` is appended only for classes with a config healAmount (baseline: /heal8)." The token slot where `/heal<n>` goes is never fixed → agents emit different prompt strings.

2. **docs/07 (line 34) — placeholder enemy sprite colour.** "enemy = the SAME color darkened 40%". What "40%" means (RGB scale, HSL lightness, overlay) is undefined → divergent placeholder fills.

3. **docs/05 (line 9) — landing Play button.** "one button `Play` (→ `/play` or `/login`)". Destination for unauthenticated users must be chosen by the implementer.

4. **docs/02 (preview, lines 104–111) vs docs/06 (line 149) — preview `moveTiles` shape.** `02`: `moveTiles: [number, number][]`. `06`: "Boolean per tile, no path enumeration" with an array-of-pairs example. Agents may implement boolean-matrix vs array differently.

## CONTRADICTIONS

1. **docs/01 (line 133) vs docs/06 (lines 104–118) — `GET /api/meta`.**
   - `01`: serves "the public subset (`classes` labels/stats/role, `personalities` labels, `themes`, `lore`) via `GET /api/meta`".
   - `06`: the example response includes `boardSize`, `maxActiveGames`, class entries with `count`/`healAmount`, and states every class in config is included (line 118).
   - Cross-doc quote conflict → agents must guess what the endpoint serves, risking frontend/backend mismatch.

2. **docs/05 (line 34) vs docs/06 (line 139) — 503 error copy.**
   - `05`: modal copy "The battlefield could not be designed — try again".
   - `06`: error body `{"error":"Battlefield generation failed, try again"}`.
   - Same event, two different strings.

3. **docs/01 (line 70) vs docs/02 (line 3) — engine location.**
   - `01`: "`src/game/` is pure and imports nothing from features".
   - `02`: "Everything here lives in `server/src/game/`".
   - Naming drift that leads agents to different paths.

## VERDICT

1. **The missing `lastAiActions` column (docs/01 vs docs/06) is the top finding** — the "exact" schema and the contract contradict each other, forcing an agent to invent where the spec forbids invention.
2. **The landing-tile wording conflict in docs/02** means validator behaviour is left open to agent interpretation.
3. **The /api/meta split between docs/01 and docs/06** creates a fork agents must resolve before any frontend or backend code is written.
